# Windows / macOS 原片源拉取修复

2026-11-10 核实：Windows 0.5.8、macOS 0.5.7 存在与 iOS 同类的问题。两端的发布源码均为 `d26b46302ac038f1749c8cb53916f739f33addba`；修复基于桌面主线 `8948f3e7eba8168589347bca1cab4238611ffcf9`，该基线的 Flutter 树与两个发布标签一致。

发布基线可核对 [Windows 0.5.8](https://github.com/Pilipala9919/MarcoMovie/releases/tag/windows-v0.5.8) 和 [macOS 0.5.7](https://github.com/Pilipala9919/MarcoMovie/releases/tag/macos-v0.5.7)。本次为未发布修复，两个现有下载包不会自动获得这些改动。

## 已复现的问题

- 桌面 `CspBridge` 把插件名称映射到内置采集池；插件加载失败也会降级到其他采集服务，原片源名称与实际内容不一致。
- 旧详情缓存可以继续携带其他来源的剧集；按片名找其他片源的逻辑也会在原源为空时自动触发。
- 另有桌面独有问题：`CatPawHost` 使用 `mm_netdisk_cred_*_v1` 读取凭据，而设置实际保存到 `netdisk_*`，导致脚本服务未拿到已保存的网盘登录状态。
- 未适配的音乐、听书、体育和聚合直播插件被当成 Bilibili / 虎牙；泛称“儿童”的插件被当成兔小贝。现已移除这些没有原服务依据的映射。

从桌面发布基线运行原源归属测试，14 项中有 13 项失败。修复后全部通过。

## 修复内容

- 删除内置采集池及跨来源自动混线。普通片源无内容或原插件失败时保留失败状态；明确的豆瓣片单仍可匹配用户导入的来源，并返回真实归属。手动换源保留。
- 将原目录、分类、搜索、详情与稳定网盘文件引用适配到桌面分支。WoGG 只使用原订阅的已审阅插件配置或明确的 `siteUrl`；未知插件版本明确报错。
- UC、百度、阿里、夸克分别读取原分享文件并重新获取临时播放凭据。保留原文件名、目录、体积和服务实际返回的画质；不通过同名影片补出“4K”线路。
- 扫码的一次性票据必须交换成真正账号会话；旧占位凭据不再显示已登录。脚本服务读取真实存储键，并在退出或失效后清除同步的旧凭据。
- 分享超时会取消后续请求。播放器切集、退出、换账号会停止旧操作；同一文件切换画质保留其本机代理生命周期。
- 拒绝旧 WoGG / Guard / 脚本缓存中的外站直链；App V2 详情请求保留配置路径及查询参数。
